# 用户和用户组管理

## 一、 为什么需要用户？

1. **登录凭证**：无论是 Linux 还是 Windows，都必须有用户才能登录系统。
2. **多用户隔离**：Linux 是一个多用户系统，允许多个用户同时登录，并运行各自的应用软件，互不干扰。
3. **权限控制**：通过用户身份来进行权限隔离，防止越权操作。

---

## 二、 用户分类与 UID (用户ID)

系统底层是**根据 UID** 来识别用户身份的，而不是用户名。每一个用户都有一个唯一的 UID。
*(注：即使是系统用户，一般也分两类，但通常我们按以下三大类划分)*

- **超级管理员 (root)**：
  - **UID 为 0**。
  - 拥有系统的最高权限（相当于 Windows 的 Administrator），可以对 OS 进行任何配置。
- **系统用户（程序用户）**：
  - **UID 范围：1 ~ 999**。
  - 专门用来运行后台服务或软件（如 `bin`, `daemon`, `ftp`）。为了安全，通常它们的 Shell 被设置为 `/sbin/nologin`，**不允许真人登录**。
- **普通用户**：
  - **UID 范围：通常 >= 1000**（在 RHEL 8/9 中默认从 1000 开始）。
  - 由超级管理员手动创建，供普通人员使用。
  - *补充说明：普通用户的 UID 上限可以在 `/etc/login.defs` 文件中修改。*

## 三、 核心配置文件解析

### 1. `/etc/passwd` (用户信息文件)

记录了用户名和 UID 的映射关系，所有用户都可以读取（部分系统在忘记密码时，进入救援模式会操作此文件）。
**示例格式**：`root:x:0:0:root:/root:/bin/bash`
由冒号 `:` 分隔为 **7 个字段**：

1. **用户名**：`root`
2. **密码占位符**：`x`（这里不是密码！代表密码保存在 `/etc/shadow` 文件中）
3. **UID**：`0`
4. **GID**：`0`（用户所属的主组 ID）
5. **描述信息**：`root`（备注，图形化界面可见）
6. **家目录**：`/root`（用户登录后的初始位置）
7. **登录 Shell**：`/bin/bash`
   - `/bin/bash`：**表示允许该用户登录**，并分配终端。
   - `/sbin/nologin`：**表示禁止该用户登录**系统。

### 2. `/etc/group` (组信息文件)

记录了 GID 和用户组的映射关系。
**示例格式**：`user:x:1000:`
由冒号 `:` 分隔为 **4 个字段**：

1. **组名**
2. **组密码占位符**：`x`
3. **GID** (组 ID)
4. **组内成员**（附加组为该组的用户列表）

## 四、 用户组管理

用户组的出现是为了更**方便地批量管理用户权限**。一个组可以包含多个用户。

### 用户组的分类：

1. **私有组（主组）**：
   - **有且只有一个**。
   - 创建用户时，如果没有指定主组，系统默认会自动创建一个与该用户同名的用户组，作为其私有组。
   - 记录在 `/etc/passwd` 的第 4 个字段 (GID)。
2. **附加组（公共组）**：
   - 一个用户可以加入 0 个或多个附加组。
   - 加入附加组的目的是为了获取该组所拥有的额外权限。
   - 记录在 `/etc/group` 的第 4 个字段中。

### 组相关的特殊命令：

- `gpasswd`：用于设置组密码（为组设定密码后，其他用户可以通过密码加入该组）。
- `newgrp`：临时切换到指定的用户组（如果该组有密码，可能需要输入密码）。

> 💡 **学习建议**：
> 考试中常考“创建一个用户并指定它的附加组”，需要熟练掌握 `useradd`、`usermod`、`id` 等命令（后续会重点学习）。理解 UID 和配置文件的关系，是做一切权限管理的前提。
